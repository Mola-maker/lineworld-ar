# 3D 人物制作需求规格书（发给美术/建模团队）

> 版本 v0.1 · 适用项目：LineWorld（手机 / 电脑摄像头 AR，现实画面线条化 + 3D 人物）
> 交付前请先用本项目自检：打开 `https://<部署地址>/?admin=1`，把 `.glb` 拖进页面，
> 右侧 **Model check (spec)** 面板必须显示 `no warnings`。面板里的每条警告都标注了对应的本文章节号。

## 0. 一页纸摘要（最常出错的 10 条）

| # | 要求 | 为什么 |
|---|------|--------|
| 1 | 交付 **glTF 2.0 二进制 `.glb`** 单文件，同时交付源文件 | Web 端唯一稳妥的运行时格式 |
| 2 | **单位：米**，Y 轴向上，人物**面朝 +Z** | 尺寸/朝向错了，人物会巨大、迷你或背对用户 |
| 3 | **原点在两脚之间的地面上**，T/A-pose 下鞋底最低点 y = 0 | 防悬空的第一前提 |
| 4 | 所有变换 **Apply（scale = 1）**，不要有缩放 ×100 的父节点 | 测试模型就有 ×20 缩放，导致描边/阴影出错 |
| 5 | 全部动画 **原地（in-place）**，根骨骼不位移 | 位移由程序控制，否则会"滑步"或飘走 |
| 6 | 待机/说话等动画 **双脚始终贴地**：不抬高、不穿地、不滑动（≤ 5 mm） | 脚一动就显得悬空 |
| 7 | 手机预算：**≤ 30k 三角面**、**≤ 3 个材质**、贴图 **≤ 2048²**、文件 **≤ 5 MB** | 中端手机 60 fps 的上限 |
| 8 | 颜色贴图里 **不要烘焙光照和投影** | 实时光照/阴影由 AR 环境估计生成，烘焙的阴影方向会穿帮 |
| 9 | 法线 **平滑（或额外提供描边用平滑法线）**，网格闭合 | 线条风格靠外描边，硬边法线会让描边断裂 |
| 10 | **著作权全部转让**，并声明是否使用了 AI 生成工具、第三方素材 | 商业上线的前提（见 §9） |

## 1. 交付物清单

| 交付物 | 格式 | 说明 |
|---|---|---|
| 运行时模型 | `.glb`（glTF 2.0） | 含网格、骨骼、蒙皮、动画、贴图，**一个文件** |
| iOS 备用模型（可选，建议） | `.usdz` | iPhone 上 AR Quick Look 可用系统级 ARKit 真实贴地，作为 iOS 的增强入口 |
| 源文件 | `.blend` 或 `.ma/.mb` / `.max` + 原始贴图（`.psd` / Substance `.spp`） | 用于后续修改，必须能独立打开（贴图路径相对化、打包） |
| 交换格式 | `.fbx`（含骨骼与动画） | 方便以后换引擎 / 原生 App |
| 设定稿 | 三视图（正/侧/背）+ 表情表 + 配色表（HEX） | 尺寸标注到厘米 |
| 预览 | 转台视频 + 每个动画的 MP4 预览 | 验收用 |
| 说明文档 | `README.txt` | 骨骼列表、动画清单（名称/帧数/是否循环/步幅）、使用的插件与第三方素材、授权证明 |

文件命名：`<角色名>_v<三位版本号>.glb`，例：`traveler_v003.glb`。每次交付附 `CHANGELOG`。

## 2. 文件格式细则（glTF / GLB）

- **glTF 2.0**，二进制 `.glb`，贴图内嵌；必须通过 [Khronos glTF Validator](https://github.khronos.org/glTF-Validator/) **0 errors**（warnings 需逐条说明）。
- 材质只用 glTF 核心 **PBR Metallic-Roughness**；不要依赖 DCC 软件的专有着色器（Blender 节点、Arnold、V-Ray 等导出后都会丢失）。
- 允许的扩展：`KHR_materials_unlit`、`KHR_texture_transform`、`KHR_mesh_quantization`、`EXT_meshopt_compression`、`KHR_materials_emissive_strength`。
  `KHR_texture_basisu`（KTX2）/ `KHR_draco_mesh_compression` 需提前沟通（需要额外解码器）。
- 压缩：我方会用 `gltfpack` / `gltf-transform` 做 meshopt 压缩，**请交未压缩版本**，压缩版本由我方生成并回传确认。
- 不要包含：相机、灯光、空物体残留、未使用的材质/贴图/动画、隐藏网格、`_Proxy` 物体。

## 3. 坐标、尺度、原点（防悬空的基础）

### 3.1 单位与尺寸
- 1 单位 = **1 米**。人物真实设定身高写入 README（例：0.95 m）。程序可以再缩放，但源资产必须是真实尺寸。
- Y 轴向上，人物**正面朝 +Z**（Blender 中为 -Y 朝前导出时勾选 `+Y Up` 即可）。

### 3.2 原点与姿态
- 场景只有 **1 个根节点**；根节点位于 **两脚中点、地面高度**（世界原点）。
- 绑定姿态（T-pose 或 A-pose）下 **鞋底最低点 y = 0，误差 ≤ 2 mm**；X/Z 居中。
- 所有物体 **Apply Transform**：根节点及网格的 location=0、rotation=0、scale=1。骨架（Armature）也不要有非 1 的缩放。
- 鞋底建成**平面**（或略带弧度但最低点在脚掌和脚跟两处），不要尖脚尖着地 —— 贴地判断看最低点。

## 4. 网格与性能预算（目标：中端手机 60 fps）

| 项 | 推荐 | 上限 |
|---|---|---|
| 三角面（含头发、配件） | 15k–25k | 30k（PC 专用版本可到 60k） |
| 材质数 / Draw call | 1–2 | 3 |
| 蒙皮网格数 | 1 | 2 |
| 骨骼数 | ≤ 60（身体）+ 头发/围巾等动力学骨骼 ≤ 20 | 100 |
| 每顶点骨骼影响 | ≤ 4，权重归一化 | 4 |
| Morph / BlendShape | 眨眼、口型 A/I/U/E/O、微笑、惊讶等 ≤ 16 个 | 24 |
| 贴图尺寸 | 1024² | 2048²，2 的幂次 |
| GLB 文件大小 | ≤ 3 MB | 5 MB |

网格要求：
- **闭合、无破面**、无重叠共面、无 n-gon、无零面积面；四边面为主再三角化导出。
- **法线平滑**：线条风格用外扩描边（inverted hull），硬边/拆分法线会让描边裂开（我们用低多边形测试模型已验证该问题）。
  若造型需要硬边，请**额外导出一套平滑法线**（放在 `COLOR_1` 或自定义属性 `_OUTLINE_NORMAL`），交付时说明。
- UV 不重叠（除对称部分），贴图有 ≥ 4 px 出血。

## 5. 骨骼与动画

### 5.1 骨骼
- 使用**标准人形骨骼命名**（推荐 Mixamo 或 VRM Humanoid 命名之一，全程一致），便于以后动作重定向和脚部 IK。
- 层级：`Root`（地面，位于原点，不做动画位移）→ `Hips` → 脊柱 / 四肢……
- 必须包含：`LeftFoot / RightFoot`、`LeftToeBase / RightToeBase`（我们后续做脚部贴地 IK 会用到）、`Head`、`Neck`。
- 头发、围巾、衣摆等软体：用额外骨骼 + 烘焙动画，或骨骼命名前缀 `Dyn_` 预留给运行时物理。

### 5.2 动画清单（第一期）

| 片段名（必须完全一致） | 循环 | 时长参考 | 要求 |
|---|---|---|---|
| `Idle` | ✓ | 4–8 s | 呼吸、轻微重心转移、看四周；**双脚锁死在地面** |
| `Idle_Look` | ✓ | 4–6 s | 待机变体，防止机械感 |
| `Walking` | ✓ | 1 个步态周期 | **原地走**；README 写明 *步幅 / 周期*（m/s），程序据此设定移动速度防滑步 |
| `Wave` | ✗ | 1.5–3 s | 首尾帧与 Idle 姿态衔接 |
| `Talk` | ✓ | 3–5 s | 上半身 + 口型 |
| `Turn_L` / `Turn_R` | ✗ | 0.6–1 s | 原地转身 90° |
| `Sit` / `Jump`（可选） | ✗ | — | Jump 落地帧鞋底回到 y = 0 |

通用要求：
- **30 fps**，导出时只保留关键帧烘焙后的动画，删除不用的曲线。
- 所有动画**原地（in-place）**：`Root` 与 `Hips` 不产生水平累计位移（Hips 可上下起伏）。
- 循环动画首帧 = 末帧，无跳帧。
- **接触帧**：任何时刻支撑脚的鞋底与 y = 0 的偏差 ≤ 5 mm，不能穿入地面，不能滑动（脚掌固定时水平移动 ≤ 5 mm）。
- 片段名 = 上表名称；如果使用其他命名，在 README 里给出映射（后台可配置映射，见项目 `config.json → character.animations`）。

## 6. 材质与贴图

- 贴图：BaseColor（sRGB）、Normal（线性，OpenGL 方向 Y+）、ORM（R=AO, G=Roughness, B=Metallic，线性）、Emissive（可选）。
- **BaseColor 中不得烘焙方向光和投影**，只允许很弱的 AO（≤ 15%）。阴影由运行时根据真实环境光方向生成，烘焙阴影会和现实方向打架，是“贴上去”感的主要来源之一。
- 风格要能和**线条化的世界**统一：建议偏扁平、色块清晰、少高光、低金属度；请同时提供一版 `KHR_materials_unlit` 或纯色块的“卡通版”材质供我们对比。
- 透明：头发/睫毛用 **Alpha Mask（cutoff）** 而非半透明混合（半透明在 AR 中排序容易出错）。

## 7. “不悬空”专项要求（美术侧）

程序侧已做：真实平面检测（WebXR hit-test）、底部自动对地、接触阴影、实时投影、环境光方向估计、与线条世界一致的描边风格。
美术侧需要保证：

1. §3.2 原点与鞋底 y = 0；**我们以最低点对地，任何低于鞋底的东西（拖地的披风、围巾末端）都会把人物整体顶起来** —— 拖地物件请与鞋底同高或略高 2–5 mm。
2. 待机动画双脚锁定（§5.2），重心转移靠胯部，不靠抬脚。
3. 鞋底可见、轮廓清晰（不要长袍完全遮住脚），观众靠“脚和影子的接触”判断是否站在地上。
4. 不烘焙阴影（§6），否则投影方向与真实环境不一致。
5. 比例真实：设定身高 0.8–1.2 m 时，头身比与真实儿童/角色设定一致，否则透视下会显得浮在前景。
6. 提供脚底接触点：`LeftToeBase`、`LeftFoot`（脚跟）两点在 Idle 中的 y 值应接近 0（我们会自动检查）。

## 8. 制作流程与验收节点

| 阶段 | 交付 | 我方验收方式 |
|---|---|---|
| 1. 设定 | 三视图、配色、表情 | 设计评审 |
| 2. 白模（Blockout） | 低模 `.glb`，正确尺寸与原点 | **拖进 App 实测**：尺寸、贴地、朝向 |
| 3. 高模/拓扑/UV | 中间 `.glb` | 面数、描边效果检查 |
| 4. 贴图 | 带材质 `.glb` | 手机实拍画面中风格是否统一 |
| 5. 绑定 | 绑定 + 测试动作 | 权重、形变、骨骼命名 |
| 6. 动画 | 全部片段 | Model check 无警告；手机上看滑步/穿地 |
| 7. 终版 | 全部交付物（§1） | glTF Validator 0 error；Android + iOS 实机验收 |

建议在合同中约定：每阶段 2 轮免费修改；第 2 阶段白模必须通过实机尺寸/贴地测试再继续，避免返工。

## 9. 版权与合同要点

- **著作权（含源文件）全部转让**给委托方，可商用、可修改、可再授权，全球、永久。
- 列出所有第三方素材（贴图、笔刷生成的素材、动作库如 Mixamo）及其许可证；禁止使用不允许商用/再分发的素材。
- **是否使用 AI 生成工具（如 Tripo、Meshy、Rodin 等）必须披露**，并说明人工修改程度 —— 纯 AI 生成内容在部分司法辖区的可版权性存疑。
- **关于“小王子”形象**：《小王子》原著及插画在多个国家仍受版权保护（如美国至 2039 年前后，法国有战时延长），角色名称与形象还受圣埃克苏佩里继承人方（Succession Saint-Exupéry）的商标保护和授权管理。
  测试阶段内部使用参考风格问题不大，**正式上线前必须二选一**：取得官方授权，或改为**原创角色**（可以借鉴“旅行者、围巾、星球”等通用元素，但不得复刻原书插画的标志性造型、配色与名称）。
- 保密：项目资料与未发布角色不得公开展示，作品集展示需经书面同意。
